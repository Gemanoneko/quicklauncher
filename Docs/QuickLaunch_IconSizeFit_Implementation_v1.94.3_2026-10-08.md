## Behavior and root causes

Previously Manager changed its local icon size optimistically, while applySettingsPatch wrote global settings before testing radial geometry. A larger size could therefore exceed a Fan/Ring work area, and Manager received no authoritative response to undo its focused slider. Q2 now checks every existing radial region before any store write, broadcast, refit or shape update. It computes exact rounded geometry using actual stored count, selected Fan direction and candidate size; empty regions use n1 geometry. Any currently valid insertion preview is checked separately at n+1. Hidden and nonprimary regions participate. Each region uses screen.getDisplayMatching of its current shown DIP rect, with the existing synthetic test work-area override taking precedence. Box width/height must fit its current work area minus48; equality fits. No numeric-cap shortcut is used, because Fan heights are non-monotonic.

Refusal returns the unchanged accepted size and exact committed copy: No room at this icon size. Use a smaller size. The whole submitted patch is rejected without changing settings, item data/order, saved regions, anchors, runtime bounds/shape, preview state or files. Accepted sizes retain the existing refresh/refit behavior. The preflight makes no neighbour moves and does not add a display fallback policy.

Accepted size changes during a valid preview require its cancellation baseline to be recalculated at the accepted size. The prior baseline retained S32 bounds after accepting S64; cancellation reproduced a220px box where284px was required. That failure is preserved in C:/Antigravity Projects/Studio Illuminati/WIP/QuickLaunch/scratch/2026-10-08-icon-fit-ender/preview-before-fix.txt. The corrected baseline retains the stored count and existing placement rules; accepted cancel and commit are independently tested. Refused changes do not enter this path and preserve the original preview byte-for-byte.

Manager waits for the authoritative result, updates the focused native range and px readout, and uses revisions to prevent stale responses or delayed settings reads from overwriting a later settlement. Existing label, range/step, focus and keyboard behavior are unchanged. The existing #update-status role=status shows the refusal/title for8s and the range title temporarily carries the same copy. Accepted size clears it. Live updater state continues behind it; offer buttons remain usable, and expiry restores the latest update status. There is no new control, markup, stylesheet, preload channel, dialog or hub notice.

Store defaults/migrations, Manager bounds writes and external state reconciliation are not new user icon-size routes and are unchanged.
